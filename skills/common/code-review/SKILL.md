# Ревью кода

## Когда использовать

Используй этот навык при ревью pull request, изменённого файла или набора коммитов.

## Порядок работы

1. Определи назначение изменения и его ожидаемый результат.
2. Проверь поведение на штатных, граничных и ошибочных сценариях.
3. Проверь обратную совместимость, безопасность и производительность.
4. Проверь тесты: они должны подтверждать новое поведение, а не только покрывать строки.
5. Сначала сообщи блокирующие проблемы, затем замечания меньшего приоритета.

## Результат

Каждое замечание содержит файл, место, причину и конкретное предложение по исправлению. Если проблем нет, явно укажи это и перечисли проверенные области.
