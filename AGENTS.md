# Инструкции для агентов registry

Эти правила относятся к работе с самим репозиторием skill registry и не распространяются на целевые проекты через `profiles`.

## Выпуск версии

Используй этот сценарий при запросах на релиз, тег, публикацию версии, обновление CHANGELOG или push registry.

1. Проверь состояние репозитория и текущий последний тег.
2. Выбери следующую SemVer-версию: исправление — `PATCH`, новый совместимый skill — `MINOR`, несовместимое изменение интерфейса — `MAJOR`.
3. Сформулируй короткие заметки о фактических изменениях.
4. Запусти CLI, передав каждую заметку отдельным `--note`:

   ```bash
   python3 tools/release v1.0.5 \
     --note "Добавлен новый навык" \
     --note "Исправлена проверка"
   ```

5. Опубликуй созданные коммит и тег:

   ```bash
   git push origin main v1.0.5
   ```

6. Проверь чистое рабочее дерево и совпадение локальной ветки с `origin/main`.

CLI сам обновляет `CHANGELOG.md`, запускает проверки, запрещает повторный тег, создаёт единый коммит и аннотированный тег. Не редактируй changelog вручную и не создавай тег отдельной командой.

Релиз завершён только после успешного push коммита и тега.
